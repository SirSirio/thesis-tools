Methodology

Spec-driven development, run by GSD

Spec-driven development is the discipline — lock decisions before plans, plans before code. GSD (“Get Sh*t Done”) is one framework that automates that loop.

1Discuss
Lock decisions before planning — binding context the planner can’t contradict.
→
2Plan
Research first, then atomic tasks — each executable in a fresh context.
→
3Execute
Parallel waves, atomic commits — reviewable at every step, not one giant diff.

GSD wraps the loop with research, verification, and atomic commits — keeping AI context lean as a project grows.
