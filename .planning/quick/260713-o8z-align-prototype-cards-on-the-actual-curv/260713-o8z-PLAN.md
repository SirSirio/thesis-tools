# Quick Task 260713-o8z: Align prototype cards on the journey curve

## Problem

In `prototypes/index.html` the journey view draws a winding SVG S-curve
(`viewBox 0 0 600 900`, `preserveAspectRatio="none"`, stretched over the
2500 px stage), but every `.proto-node` card is pinned at `left: 50%` —
the cards form a straight center column while the curve sways ±64 SVG
units (≈ ±10.6 % of stage width) beneath them.

## Approach

Sample the real `.journey-path` element at runtime with
`getTotalLength()` / `getPointAtLength()` (user units are unaffected by
the `pathLength="1"` attribute), find the path point whose y matches
each card's vertical center, and set the node's inline `left` as a
percentage (`x/600 · 100 %`). The existing `translateX(-50%)` transform
keeps the card centered on that point. Because the SVG is stretched
non-uniformly, viewBox units map linearly to stage fractions — no
matrix math needed.

## Tasks

1. **Add `alignNodesToPath()` to the inline script** in
   `prototypes/index.html`:
   - Skip (and clear inline `left`) when the path SVG is
     `display: none` (mobile ≤ 640 px — nodes are `position: static`
     there, inline `left` must not leak back on resize to desktop).
   - Sample ~240 points along the path; for each `.proto-node`, map
     `offsetTop + offsetHeight/2` → SVG y (`/stageHeight · 900`), pick
     the nearest-y sample, set `left = x/600·100 %`, clamped so the
     card never overflows the stage.
   - Run immediately (script is at end of body), again on window
     `load` (proto-01 photo changes card height), and on `resize`.

2. **Update `prototypes/SPEC.md`** journey-view section: nodes are
   positioned on the path by runtime sampling, not a fixed center
   column.

## Verification

- Serve locally, load the page in a browser: the five cards sway
  left/right following the orange curve (≈ 59 %, 46 %, 44 %, 59 %,
  40 % of stage width at current content heights).
- Narrow the window below 640 px and back: mobile stack unaffected,
  desktop alignment restored on resize.
- No horizontal scroll at any width (project constraint).
