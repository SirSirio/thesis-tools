# Quick Task 260720-l0e — Arduino Nano as a design option + missing-variant sweep

## Goal

Make the Arduino Nano (a board Sirio already uses and owns) a represented design
option in the System Architecture Explorer, and sweep the 20-variant set for any
other genuinely-missing, worth-adding variants — keeping tool data, PIN-BUDGET-ANALYSIS.md,
and SPEC.md in sync.

## Sweep result (what's missing, what's not)

- **Missing & worth adding:** a **single Nano pump-node driving DRV8825** at **2-concurrent**.
  The tool already models satellite nodes with RP2040 (`P6-rp-*`), STM32 (`P6-stm-485`), and
  a Nano *TMC2209* node (`T9-node-485`), plus 6× Pro-Mini distributed — but **not** a Nano
  driving the *dumb* DRV8825s. That is exactly Sirio's in-house hardware (1 Nano + DRV8825).
  A Nano's 2 usable hardware timers cap it at ~2 clean concurrent trains → aligns perfectly
  with the validated **U5 = 2** decision, and the node offloads the 6-driver fan-out off the
  ESP32 so DRV8825 finally fits the pin budget. All-bitbyg-sourceable.
- **Considered, NOT added (with reason):**
  - *Nano as brain* — excluded on purpose: cannot render the GUI + hold system logic (ESP32-class
    required). Already stated in the tool.
  - *Nano-per-pump distributed* — already covered by the Pro-Mini `P6-dist-*` rows (same shape).
  - *A4988 dumb driver / ESP32-S3 brain swap* — not new topologies, just part swaps; out of scope.
  - *Nano node on CAN* — overkill for a 3-node system; RS-485 already covers the robust-bus case.
