<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user-typed price inputs → `COMP[k].eur` → matrix render | The only untrusted-ish input surface. Numeric fields only; values are clamped (`Math.max(0, parseFloat(...)||0)`, line 844) and re-serialised as numbers. |
| `localStorage` (`sae-prices`, `sae-prices-v`, `sae-rate`) → `loadPersisted()` | Same-origin, single-user, offline. Parsed inside `try/catch` with `Number.isFinite(v) && v>=0` guards. Not a security boundary — a user editing their own localStorage attacks only themselves. |
| author-authored `source.note` / `source.url` strings → component table DOM | Static, in-repo strings this plan adds. Rendered via `sourceCellContent()` (`createElement`/`textContent`), never `innerHTML` interpolation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06.1-01 | Tampering | New `DEFAULTS` `source.note`/`source.url` strings rendered into the component table | mitigate | Task 1 mandates rendering through the existing `sourceCellContent()` helper (index.html:806–824) and forbids `innerHTML` string concatenation of note/url values. `sourceCellContent()` additionally gates `href` on `/^https?:\/\//i`, blocking `javascript:` URLs. |
| T-06.1-02 | Tampering | `localStorage` price snapshot surviving a `DEFAULTS` schema change | mitigate | Task 1 bumps `PRICES_VERSION`, invalidating stale snapshots on load (existing Phase-6 D-06 mechanism). Existing `Number.isFinite && >=0` guard rejects malformed/negative persisted values. |
| T-06.1-03 | Information Disclosure | Outbound `<a href>` links to bitbyg product pages | accept | Links already carry `target="_blank" rel="noopener noreferrer"` via `sourceCellContent()`. Referrer leakage to a public vendor page is not a concern for a public thesis site with no PII. |
| T-06.1-SC | Tampering | Supply chain (npm/pip/cargo installs) | not applicable | No package manager exists in this project (CLAUDE.md: no build tools, no npm, no frameworks). This plan adds zero dependencies. No slopcheck or legitimacy gate applies. |

**Not applicable, and why:** Spoofing / Repudiation / Elevation of Privilege — no authentication, no
sessions, no accounts, no server, no roles. SQL injection, CSRF, SSRF, authn/authz bypass — no
backend, no database, no state-changing requests, no server-side fetch. The page is a static file
that can be opened from a USB drive with no network.
</threat_model>
