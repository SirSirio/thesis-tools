<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `#fDir` `<select>` value → `selectedDirection` → `renderMatrix()` filter | `<select>`-constrained: no free text can reach it. Pure UI state; never persisted, never reaches `innerHTML`. |
| gallery card `data-*` key → `setDirection(key)` | Keys originate from the in-repo `DIRECTIONS` object. A tampered DOM attribute can only produce a key that matches no variant. |
| `DIRECTIONS` name/copy strings → gallery DOM + `directionPill()` `innerHTML` | Static author-written in-repo strings. `directionPill()` returns an `innerHTML` fragment, matching the existing `conPill()` idiom. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06.1-07 | Tampering | `directionPill()` interpolating `DIRECTIONS` display names into the matrix row `innerHTML` template | mitigate | Direction names are static, author-written literals in the `DIRECTIONS` object — never user input, never persisted, never read from `localStorage`. Keep them alphanumeric with no markup, exactly as `conPill()` (index.html:790) already does for its static pill labels. If a name ever needs a non-trivial character, route it through the existing `escapeHtml()` (index.html:793). |
| T-06.1-08 | Tampering | `setDirection(key)` reading a key from a DOM `data-*` attribute | mitigate | Validate the key against the `DIRECTIONS` object and no-op on a miss; never use it to index anything outside `DIRECTIONS`. An unknown key must degrade to the no-filter sentinel, not throw. |
| T-06.1-09 | Denial of Service | `renderMatrix()` re-running on every gallery click / dropdown change | accept | Bounded work: 20 variants, a `.filter()` + `.sort()` + DOM rebuild — the same cost the existing four filter controls already incur on every change. Client-side, single-user, offline; there is no shared resource to exhaust. |
| T-06.1-SC | Tampering | Supply chain (npm/pip/cargo installs) | not applicable | No package manager in this project (CLAUDE.md: no build tools, no npm, no frameworks). This plan adds zero dependencies — the sketches are inline SVG. |

**Not applicable, and why:** Spoofing / Repudiation / Information Disclosure / Elevation of
Privilege — no auth, no sessions, no accounts, no server, no roles, no PII. SQLi, CSRF, SSRF,
authn/authz bypass — no backend, no database, no state-changing requests, no server-side fetch. The
direction filter is UI state that is not even persisted to `localStorage`.
</threat_model>
