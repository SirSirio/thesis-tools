evidence: |

    post-phase @1440: clientWidth 1425, scrollWidth 1551, overflow 126px, window.scrollTo(500,0) → scrollX 126 (page really scrolls)
    pre-phase  @1440: clientWidth 1425, scrollWidth 1425, overflow 0px, no .matrix-wide element

       correctly-centred card would be 15px too wide.
  body{overflow-x:hidden} (assets/style.css:23) does not contain it because html is overflow-x:visible.

  Mobile is NOT affected and NOT a regression: at 390px the @media(max-width:640px) rule
  ({width:100%; align-self:stretch}) contains .matrix-wide correctly (18→357 in 375px). The
  23px overflow that remains at 390px comes from the .ctl/#ifMode controls block and is
  PRE-EXISTING — the pre-phase build measures an identical 398/375/23 at that width.
