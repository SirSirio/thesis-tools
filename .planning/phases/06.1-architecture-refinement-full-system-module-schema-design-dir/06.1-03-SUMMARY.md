# Phase 06.1 Plan 03: Design-Direction Gallery + Design-Type Matrix Column Summary

**Four-card SVG design-direction gallery (Distributed Modules / All-in-One / Console / Panel + Node) inserted between the module schema and the theory section, feeding a new sortable "Design type" matrix column and a shared `selectedDirection` filter wired to both the gallery and a new `#fDir` dropdown, plus a break-out-width matrix container.**

## Accomplishments
- `directionOf(v)` classifies all 20 variants into exactly four buckets (2 modular / 2 allinone / 8 console / 8 panelnode), derived entirely from existing `topoClassOf(v)`/`intBrainKey(v)` — verified via direct Node VM execution of the live code against the real `VARIANTS` array, matching the plan's exact specified membership with zero unclassified or double-bucketed rows
- `DIRECTIONS` object holds each direction's display name, CSS colour class, and 1-sentence copy (well under the 2-sentence cap) as the single vocabulary read by both the gallery and the matrix chip — verified no direction name literal appears in more than one place in the file
- `directionSketch()` draws a small device-impression SVG per direction (one integrated board vs a discrete screen + separate MCU vs a screen-brain + node vs a screen + a row of per-pump modules) — never an abstract topology chart, reusing `buildDiagram()`/`buildSchema()`'s template-string closure technique
- `#directions` gallery sits between `#system` and Part 01 as real `<button>` cards (natively focusable, Tab/Enter/Space work with zero extra keyboard code); the `--delay` stagger was renumbered from 0.06s onward in consistent 0.015s steps to make room, ending at 0.225s for the diagram `.sae-card` (was 0.17s) — still monotonically increasing in document order
- Matrix gained a 10th column ("Design type", second position after ID), a `directionPill(v)` helper mirroring `conPill()`'s shape, four new `.dir-*` colour classes, a string-comparison sort branch, and the detail-row `colspan` bumped from 9 to 10 (verified zero remaining `colspan="9"` in the file)
- `selectedDirection` shared state extends the existing `maxPrice`/`maxCx`/`minCon` filter shape; `setDirection(key)` is the sole writer, validating the key against `DIRECTIONS` and syncing both the gallery's `.selected` class and the `#fDir` `<select>` value in one place so the two entry points can never disagree
- `.matrix-wide` breaks the solution matrix out to `calc(100vw - 64px)` capped at 1500px (rotor-solver's `.glass-panel--wide` precedent), disabled at the existing 640px breakpoint so mobile never sees a wider-than-viewport table
- Verified the full interactive flow end-to-end via a Node VM sandbox with a minimal fake-DOM harness: card click sets the filter and updates `#rowCount` to "8 of 20" for `console`, re-click restores "20 of 20", `setDirection()` keeps the dropdown and card `.selected` state in sync, an unrecognised key degrades to the no-filter sentinel, and a zero-result filter combination clears the diagram without throwing

## Decisions Made
- Direction display names (Claude's Discretion): Distributed Modules / All-in-One / Console / Panel + Node
- Four new pill colours chosen in hue gaps unused by the existing accent/accent-2/ok/warn/blue palette (violet #b06bf5, teal #3ecfae, pink #f06bc4, indigo #7a6bf0)

- `C link` was left visible at all breakpoints (no `hide-sm` added) — the plan permits adding it only if the 10-column table "proves too tight," which requires a browser layout observation this session could not perform
