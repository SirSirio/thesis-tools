## Fixed

### CR-01 — "whole-system cost" toggle emptied the matrix (`f6b6cf4`)

**The one functional break in the phase.** Plan 06.1-01 rebuilt `SHARED_BOM` from
€137.22 to €149.65, pushing every whole-system cost (€207.61–€341.48) above the
`#fPrice` slider's `max="200"` ceiling. Selecting "whole-system cost" rendered
`0 of 20 variants shown.`, blanked `#diagram`, and set `selectedVariantId=null` —
with the slider already at its maximum there was no recovery path.

Fix: fixed €400 ceiling (user's choice from three options — the alternatives were
per-view rescaling and a data-derived ceiling). Four sites updated in lockstep so
the markup, label, and JS initial state agree: `#fPrice` `max`/`value`, the
`#maxPriceLbl` span, and `let maxPrice`.

Verified against the live constants:

| view | range | rows at max |
|---|---|---|
| controller-only | €65.71–€191.83 | 20/20 |
| whole-system | €207.61–€341.48 | 20/20 |

A comment at the `<input>` records the invariant: the ceiling must stay above the
dearest whole-system variant whenever `DEFAULTS`/`SHARED_BOM` change.

### CR-04 — Part 01 theory prose disproved by its own price table (`9086c10`)

Four claims corrected, all verified against the shipped `DEFAULTS`:

| claim | shipped reality |
|---|---|
| "Dumb driver (DRV8825, ~€1.5)" | €6.87 |
| "TMC2209 … ~€3.5" | €3.50 ✓ (only survivor) |
| "roughly €2 more per driver on a smart part" | TMC2209 is **€3.37 cheaper** (6× = €21.00 vs €41.22) |
| "Rows at 1–2 concurrent … sit around €29–30" | €72.53–€77.55 |

Hard-coded prices were dropped rather than updated — the prose now defers to the
live table, so it cannot drift again on the next sourcing pass.

**Beyond the review's finding:** checking the €29–30 figure surfaced that the
paragraph's *conclusion* is also inverted. It claimed "concurrency, not driver
family, sets the floor cost and the floor complexity". On the sourced prices the
cheapest 6-parallel row (`T9-fused-i2c`, €65.71) **undercuts** the cheapest
single-pump row (`S1-i2c`, €72.53) — cheap TMC2209 drivers more than offset the
larger 150 W PSU. The PSU and complexity floors *do* still hold (every `at=6`
variant takes `psu150` and `cx>=2`), so those claims were kept; the cost-floor
claim was replaced with what the data actually shows. This is arguably a stronger
result for the thesis and is flagged for the author's review.

### CR-02 — SPEC's "1 pin free" vs the shipped 0 (`a2a3f3a`)

`pinsOf(ESPINT32-brain-i2c)` returns `{used:3, avail:3, free:0, overrun:false}`.
SPEC claimed 1 free. The D-13 vibration PWM pin added in 06.1-01 consumed the last
GPIO; SPEC's own pin formula already included the `+1` term, so the file
contradicted itself. Prose now states zero pins to spare and shows the derivation.
