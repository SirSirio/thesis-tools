# Plan 10-01 — Shared prototype-subpage stylesheet

**Wave:** 0 (blocking — 10-02, 10-03, 10-04 all consume its output)
**Creates:** `assets/prototype-page.css`
**Modifies:** nothing

## Goal

Extract every CSS rule that the *detail views* of `prototypes/index.html` depend on into a
single shared stylesheet, so the three prototype subpages built in wave 1 share one visual
system instead of inventing three.

## Why

Three subpages sharing one look is exactly the case `assets/deck.css` was sanctioned for.
Duplicating ~400 lines of detail-view CSS three times would guarantee drift.

## Tasks

1. Read the inline `<style>` block of `prototypes/index.html` (lines ~9–642).
2. Classify every rule into one of three buckets:
   - **JOURNEY** — only used by `#journey-view` (`.journey-*`, `.stage-inner`, `.nodes-layer`,
     `.proto-node`, `.proto-card*`, `.kpi-pill`). **Leave behind** — stays inline in the
     journey page, which plan 10-05 rewrites.
   - **DETAIL** — used by `#detail-view` / `.detail-section` / `.detail-block` and everything
     inside them: headings, tables, callouts, equation chips, version panels, TOC, lightbox,
     figure/media, bars. **Extract to `assets/prototype-page.css`.**
   - **SHARED-ALREADY** — duplicates of rules already in `assets/style.css` (nav, blobs,
     body, fade-up). **Drop** — the subpages link `assets/style.css` too.
3. Write `assets/prototype-page.css` containing the DETAIL bucket, plus:
   - A **subpage shell**: `.proto-page`, `.proto-page-header` (eyebrow + title + status
     chips + one-line summary), `.proto-page-body`, and a `.proto-toc` sidebar/inline TOC.
   - The **per-page accent hook**, defaulting to the pump orange so existing pages are
     unchanged:
     ```css
     .proto-page { --p-accent:#ff6b2b; --p-accent-2:#e83535; --p-accent-soft:#ffb08a;
                   --p-glow:rgba(255,107,43,.25); --p-border:rgba(255,107,43,.18); }
     .proto-page--align { --p-accent:#9b7fe0; --p-accent-2:#5a8fd8; --p-accent-soft:#c3aef5;
                          --p-glow:rgba(155,127,224,.28); --p-border:rgba(155,127,224,.22); }
     ```
     Repoint every extracted rule that hard-codes orange at these variables. Semantic colours
     that are *not* the page accent — the green "good" callout, the red "warn" callout, the
     blue CAD/internal chips, the version chips — keep their own literals.
   - Responsive rules so no page scrolls horizontally at 320px. Tables that cannot wrap get
     their own `overflow-x:auto` wrapper class (`.table-scroll`); the page body never scrolls.
4. Do **not** modify `prototypes/index.html`. This plan is additive only.

## Verification

- `assets/prototype-page.css` parses (no unbalanced braces): `node -e` brace count or a CSS
  lint pass.
- Every selector in the file is reachable from a `.proto-page` root, or is a `@media` /
  `:root`-level rule.
- No `rgba(255,107,43` or `#ff6b2b` literal remains in a rule that should follow the page
  accent — grep and justify each survivor.

## Deliverable back to the orchestrator

A short **class contract**: the list of structural classes a subpage must use
(`.proto-page`, `.proto-page-header`, `.detail-block`, `.table-scroll`, callouts, chips,
figure, lightbox hooks, TOC), so wave-1 agents write matching markup without re-reading
the stylesheet.
