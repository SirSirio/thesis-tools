<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage → page | The `lang` key selects a dictionary branch |
| inline LANG dict → DOM | `applyLang()` assigns values via `innerHTML` |

Static page, no server, no auth, no sessions, no user input, no network calls at runtime. Injection,
CSRF, and session threats have no surface here and are deliberately omitted rather than padded in.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-10 | Tampering | `localStorage['lang']` read after this phase's edits | mitigate | The existing guards must survive the collapse and the copy edits: the read stays try/catch wrapped and `if (!LANG[currentLang]) currentLang = 'en'` still validates the value before it indexes the dict. Task 2's checker asserts both, so a refactor cannot quietly drop them (LANG-03, LANG-04) |
| T-07-11 | Tampering | `applyLang()` `innerHTML` with edited copy | accept | Same disposition as T-07-04 and T-07-07: values are author-controlled constants in the same document. Sirio's copy edits change the constants, not the trust model. No fetch, no URL parameter, and no localStorage value ever reaches `innerHTML` — only the `lang` key does, and only as a validated branch selector |
| T-07-12 | Information disclosure | Broken/dangling links after the section collapse | mitigate | Deleting the Prototypes section risks orphaning a destination. Task 2's checker asserts all 8 hrefs are present, and checkpoint step 3 clicks every one. Not a security issue so much as an integrity one, but it is the real failure mode of this plan |
| T-07-SC | Tampering | npm/pip/cargo installs | n/a — no installs | Zero packages installed.
