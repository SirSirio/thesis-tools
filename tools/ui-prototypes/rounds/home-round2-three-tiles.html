Home — round 2: three destinations, and liquids that report rather than alarm

Three changes carried into all three layouts: Fill lines has left Home, Start a run and Recipes are the two primaries, and the Liquids tile shows the six levels instead of only a verdict — with the new severity rule (red only when everything is empty). The colour treatment from round 1 is now a switch, so layout and colour can be judged separately.

Outcome: option D with colour rails was chosen and built on 2026-08-11 — the simplest of the three and the one that asks the operator to relearn the least. E and F are kept here as the record of what was tried and rejected, and both remain reachable positions if a later session finds D's band does not read as tappable.

The new liquid rule

Today liquid_severity() returns red as soon as one liquid is below 15 %, unreadable or has no bottle. That is wrong for the way the machine is used: a protocol may need two of the six, and an empty bottle on a channel nobody is using is not an emergency. The rule in these mockups:

ConditionTileWord
every fitted liquid ≥ 33 %normal, green accent"All six ready"
some below 33 %, unreadable or no bottleamber"4 of 6 low or empty"
all of them empty / unreadablered"ALL SIX EMPTY"

The count and its denominator do the real work — "4 of 6" is actionable, "NEEDS ATTENTION" is not. The pre-run check is where a shortage still blocks, and it already knows which liquids the chosen recipe actually needs, so Home does not have to guess. An unknown level still counts as bad, never as fine (defect V1-2).

What the tile looks like when nothing is wrong — the six bars

You asked how the Liquids tile should be designed if it never had an error to report. Answer: stop making it a verdict and make it a gauge. Six bars, one per channel, in the channel colours already used everywhere else, each with its numeral. In the healthy state it is a status readout worth glancing at; in the amber state the short bars are the message and the word only counts them. That also settles open question 3 in UI-EVOLUTION.md — the levels are visible at a glance again, without Home scrolling, which is what dropping the fourth tile bought.

Consequence worth flagging: the Liquids tile can no longer go solid red, because a solid fill destroys the bars. In the "all empty" state it takes the same treatment as the position warning — pale red ground, 2 px red border, red ink — which is already this interface's blocking look, so it is not a new visual language.

The sub-lines, rewritten (operator, same session)

A sub-line is a sentence: it starts with a capital and it says what is, not what you may do. Two under the home tiles failed that and are worth not repeating. "recipes and tubes" named what the next screen asks for — nothing the operator can act on — and is now "Set up, then run", which earns its place by setting the one expectation that matters: pressing it does not energise anything, the run starts at START on the pre-run check. "add or edit - 10" hung a count off a verb it had nothing to do with, so the number read as part of an instruction; it is the contents, so it now reads "10 recipes" ("1 recipe", "None saved yet"). The rule is recorded as rule 3 at the top of ui_screens.h and was applied to every sub-line in the interface, not only Home.

Where Fill lines went

Out of Home, into Settings → FILL TUBING, beside the LINE VOLUME and EXTRA DOSE fields it belongs with (scr_misc.cpp:144). Nothing is lost from the run path: the pre-run check already routes to the fill screen when a line is unfilled, and the prime-check question added for finding F5 does the same (scr_run.cpp:370, :386). Filling stops being something the operator is invited to do at idle and becomes what it actually is — a step of starting a run, plus a maintenance action in Settings.

Layout trade-offs, honestly

  • D — chosen and built. Keeps Start a run and Recipes exactly where they are today, so nothing already learned is invalidated, and it is the least elaborate of the three: two buttons and a readout. The open risk, recorded rather than resolved: the band reads as a status strip, and it must still be obviously tappable — to be checked on the panel.
  • E is the most microwave-like: three targets of 96 × 152 px (19 × 31 mm), far above every standard's finger minimum, so it is the only layout here that would work without the stylus. Costs the sub-lines some width and moves both primaries.
  • F gives the levels a permanent gauge and the two actions a wider label column, at the price of narrower action tiles (196 px) and the most rearrangement.

All three keep: BACK/primary placement rules, ≥ 44 px targets, no colour-alone states, no scrolling, and one solid accent per screen.
